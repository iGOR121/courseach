# lanchat

[English](README.md) | **Русский**

Небольшой peer-to-peer чат для устройств в одной **Wi-Fi / локальной сети**.
Без сервера, без интернета, без аккаунтов и без сторонних пакетов — только
стандартная библиотека Python.

Устройства находят друг друга автоматически по UDP-мультикасту и отправляют
сообщения напрямую друг другу по TCP.

В пакете два интерфейса: терминальный (`python3 -m lanchat`) и графический на
Tkinter (`python3 -m lanchat.gui`). Они используют один бэкенд и могут
общаться между собой.

## Требования

- Python 3.8+
- Все устройства в одной локальной сети (один Wi-Fi роутер / LAN)

`pip install` не нужен.

## Быстрый старт

Запустите приложение на двух (или более) устройствах:

```bash
python3 -m lanchat --nick alice     # на первом устройстве
python3 -m lanchat --nick bob       # на втором устройстве
```

После запуска:

```
Signed in as alice  |  listening on port 57092
> /peers
Peers (1):
  [1] bob @ 192.168.1.23:57093
> /to bob
Now talking to bob (192.168.1.23:57093).
[bob]> hey bob, can you hear me?
```

Строки в примере — это реальный вывод приложения (CLI выводит его на английском).

### Графический интерфейс на Tkinter

Если хочется окно, запустите GUI:

```bash
python3 -m lanchat.gui --nick alice
```

В нём есть список пиров, окно чата, смена никнейма и диалог **Add peer**. Он
использует тот же бэкенд `App`, поэтому GUI и CLI могут общаться между собой.
Tkinter входит в стандартную библиотеку Python, но в некоторых
Linux-дистрибутивах поставляется отдельно (например,
`sudo apt install python3-tk`). `pip install` по-прежнему не нужен.

## Команды CLI

| Команда | Что делает |
| --- | --- |
| `/peers` | Показать пиров (с номерами) и отметить текущего собеседника |
| `/to <peer>` | Выбрать, кому отправлять обычный текст |
| `/msg <peer> <text>` | Отправить одно сообщение, не меняя собеседника |
| `/me <text>` | Отправить сообщение-действие (`* alice waves`) |
| `/nick <name>` | Сменить никнейм |
| `/add <host> <port> [nick]` | Добавить пира по адресу (поддерживается и `host:port`) |
| `/clear` | Очистить экран |
| `/help` | Показать справку |
| `/quit` | Выйти |

Вместо `<peer>` можно указать никнейм, префикс никнейма, номер из `/peers` или
адрес `host:port`.

Если в сети ровно один пир, можно просто печатать сообщения — они уйдут ему без
`/to`. Текущий собеседник показывается в приглашении в квадратных скобках,
например `[bob]>`.

## Параметры CLI

```
-n, --nick NAME          никнейм, максимум 64 символа (по умолчанию: имя пользователя ОС)
    --group ADDR         multicast-группа (по умолчанию: 239.255.42.99)
    --discovery-port N   порт обнаружения (по умолчанию: 47820)
    --tcp-port N         фиксированный TCP-порт (по умолчанию: случайный)
    --no-color           отключить цветной вывод
```

Два экземпляра на одной машине работают нормально (удобно для тестирования).
Используйте `--discovery-port` / `--group`, чтобы запускать отдельные «комнаты».

GUI принимает те же `--nick`, `--group`, `--discovery-port` и `--tcp-port`;
подробности — в `python3 -m lanchat.gui --help`.

## Как это работает

```
            UDP multicast 239.255.42.99:47820
        ┌──────────────► announce: "I am bob, TCP port 57093"
        │
   ┌────┴────┐                                        ┌─────────┐
   │  alice  │──── TCP connect to bob:57093 ─────────►│   bob   │
   │ :57092  │      newline-delimited JSON            │ :57093  │
   └─────────┘                                        └─────────┘
```

- `lanchat/discovery.py` — каждый узел каждые 3 секунды объявляет
  `{id, nick, tcp_port}` в multicast-группу **и** на широковещательный адрес,
  потому что некоторые сети пропускают одно, но не другое. Когда он впервые
  слышит нового пира, он также отправляет ему **прямое unicast-приветствие**,
  чтобы устройство, не получающее multicast (частая проблема в Wi-Fi), всё
  равно было обнаружено. Пиры, о которых не слышно 12 секунд, удаляются; кадр
  `bye` при выходе убирает их сразу. Он отправляется и напрямую известным
  пирам, чтобы устройства, работающие только с unicast, тоже это заметили.
  Multicast также позволяет двум экземплярам на *одной* машине видеть друг
  друга.
- `lanchat/transport.py` — небольшой TCP-сервер. Каждое сообщение открывает
  короткоживущее соединение, записывает кадры и закрывает его, поэтому
  оборванное соединение не оставляет после себя сломанный чат. Соединения
  обрабатываются по одному, что сохраняет порядок сообщений от одного
  отправителя.
- `lanchat/app.py` — связывает всё вместе и предоставляет терминальный интерфейс.
- `lanchat/gui.py` — опциональный графический интерфейс на Tkinter поверх того
  же `App`.

## Тестирование

Сквозной самотест запускает два узла и проверяет обнаружение, обмен сообщениями
(включая порядок сообщений), смену никнейма и выход:

```bash
python3 selftest.py
```

Второй тест проверяет резервный механизм обнаружения для устройств, которые не
получают multicast, имитируя телефон, способный принимать только unicast:

```bash
python3 test_discovery_fallback.py
```

## Обёртки для платформ

Python-приложение — эталонная реализация; две обёртки ниже построены на нём и
используют тот же сетевой протокол, поэтому любые их комбинации могут общаться
между собой.

### macOS — `dist/LanChat.app`

Приложение, которое можно запустить двойным кликом. Соберите его один раз:

```bash
./macos/build_app.sh
```

Скрипт сборки вручную собирает `dist/LanChat.app` и вкладывает внутрь пакет
`lanchat` (поэтому приложение самодостаточно и его можно переместить, например,
в `/Applications`). Двойной клик открывает Terminal и запускает чат, используя
ваше имя пользователя macOS как никнейм. Нужен Python 3 из Xcode Command Line
Tools; если их нет, окно Terminal объяснит, как их установить.

Обёртка запускает Terminal через **LaunchServices** (`open -a Terminal`), а не
через AppleScript `tell application "Terminal"`. Apple Events требуют от
пользователя разрешения Automation, которого неподписанные приложения часто не
могут получить, что приводит к ошибке:

> LanChat has no permissions for sending Apple Events (receiver: Terminal)

Использование `open` полностью обходит это разрешение.

Перезапускайте скрипт сборки после изменения любого Python-кода.

#### Если вы всё ещё видите ошибку «Apple Events»

Она появляется из-за старой сборки на AppleScript. Удалите старый bundle и
очистите устаревшее решение macOS, записанное для него:

```bash
rm -rf dist/LanChat.app
tccutil reset AppleEvents        # очищает ВСЕ разрешения Automation, не только для этого приложения
./macos/build_app.sh
```

Пересоберите и дважды щёлкните по свежему `dist/LanChat.app`.

### Android — `android/`

Нативное приложение на Kotlin, реализующее тот же протокол (Android не может
напрямую запускать Python-код). В нём один экран: никнейм, выбор пира,
переписка, поле ввода.

Приложение собирается (`assembleDebug`) с помощью SDK Android Studio; откройте
папку `android/` в Android Studio и нажмите Run. Подробности в
`android/README.md`.

### Совместимость

Для общения между компьютером и телефоном в одном Wi-Fi:

```bash
python3 -m lanchat --nick laptop          # на компьютере
# ...и запустите Android-приложение на телефоне
```

Они должны найти друг друга за несколько секунд. Обнаружение использует UDP
multicast, который некоторые роутеры блокируют (см. «Устранение неполадок»).

**Примечание о симуляторе Android:** он работает за виртуальным NAT, поэтому
компьютер не может подключиться *обратно* к нему, и отправка завершается с
«Connection refused». Используйте реальный телефон или пробросьте порт:
`adb forward tcp:47821 tcp:47821` и `/add 127.0.0.1 47821`. Подробности в
`android/README.md`.

## Устранение неполадок

- **Пиры не появляются.** Проверьте, что все устройства в одной сети и что
  фаервол разрешает Python принимать UDP/TCP. Некоторые роутеры (и многие
  «гостевые» Wi-Fi сети) блокируют multicast/broadcast между клиентами — обычно
  это называют «AP isolation». На macOS разрешите входящие подключения, когда
  система спросит.
- **Обнаружение заблокировано, но вы можете пинговать друг друга.** Используйте
  ручной вариант: `/add 192.168.1.23 57093` (порт показан в стартовом баннере
  на другой стороне).
- **Разные «комнаты» / тестирование на одной машине.** Дайте каждому экземпляру
  свой `--discovery-port`.

## Примечания и ограничения

- Сообщения передаются открытым текстом и **не шифруются** — приложение
  рассчитано на доверенную локальную сеть.
- Если пир офлайн, отправка просто сообщает, что он недоступен; очереди
  сообщений для офлайна нет.
- Пока только LAN. Bluetooth и Wi-Fi Direct не реализованы; для нового
  транспорта нужно реализовать тот же интерфейс announce/send.
